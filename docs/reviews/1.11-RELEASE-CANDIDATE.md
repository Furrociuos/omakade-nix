# Omakade 1.11 release candidate

Local candidate only. Publication is pending maintainer acceptance and explicit approval.
The published baseline is 1.10.0. Sessions, Stats and Stop Games are integrated on
`codex/release-1.11-hardening`; the original feature worktrees are preserved.

## Included

- Now Playing, per-session stop controls, file-picker title attribution, optional pause on
  focus loss, imported/recorded playtime reconciliation, and optional Discord presence.
- Full paged session history with confirmed single-session and whole-game deletion.
- Stats and the local PNG Year in Review card, with persistent period selection.
- Per-game and global Stop Games with verified process attribution and visible scope warnings.

## Review corrections

| Area | Correction |
| --- | --- |
| History deletion | Delete and watermark update commit together; the live store reloads watermarks before refreshing totals. Failed updates preserve history. |
| Stats storage errors | Required query failures clear figures, show an error, and prevent card export. Related reads share one SQLite snapshot. |
| Calendar figures | Period totals, hours, weekdays and played days use the same clipped interval, including midnight, New Year, leap days and DST. Long sessions are not silently truncated. |
| Paused sessions | Aggregate historical durations cannot locate individual pauses. Their time-of-day allocation is explicitly labelled as an estimate. |
| Linked games | Backlog metrics use the same linked identity as ranking and headline figures. Unknown historical content does not inherit a guessed console. |
| Recorder recovery | Recovered sessions retain their start timestamps. Cache invalidation fingerprints actual title/path contents, including equal-length renames. |
| Discord | Unchanged activity is republished after disconnect. Successful replies with a null event are accepted. |
| Stop attribution | Documents passed to editors, file managers, backup tools and log viewers are not game identities. Idle Wine/Flatpak installations are not shown as running. Shared scopes are deduplicated. |
| Stop safety | Scope actions require live process evidence; forced escalation checks original process identities. A replacement game is not force-stopped by an earlier request. |
| Card export | The complete card fits its fixed image size, including long notes. Headless synthetic exports require an explicit fixture flag. |
| Stop UI | Refused starts leave the pending state, show an explanation and refresh the preview. Now Playing reports failures and uses monotonic close deadlines. |

## Validation and candidate identity

The versioned local installation's `candidate.json` identifies its exact source commit and
binary hashes. Keep its validation logs and acceptance results with that manifest. This
checklist does not establish a passing test run or authorize publication.

Required local checks: complete Release and Debug suites, repeated library reflow checks,
card/history/stop visual inspection, desktop and AppStream validation, staged startup,
package file inspection, SBOM generation and a current dependency scan. Debug builds may use
`-g1` to limit disk use while retaining assertions and unoptimized code.

## Remaining acceptance

Automated fixtures do not establish real gameplay, live Discord compatibility, physical
controller behavior or ARM64 hardware acceptance. Failed recorder writes still have a bounded
64-entry in-memory retry queue; shutdown or sustained storage failure can lose pending entries.

Maintainer checklist for the exact installed candidate:

1. Launch a game, then load one through an emulator's file picker. Check Now Playing and
   recorded duration. Check optional pause on focus loss and resume.
2. Restart the GUI and recorder during a disposable test session. Confirm the original start
   time and accumulated play remain sensible.
3. Delete a finished session, play again, and verify totals increase without restarting the GUI.
   Browse older history pages and cancel a whole-history deletion.
4. Open Stats, switch periods, restart, and compare the real library totals. Export the card,
   open its folder and check the image. Repeat navigation in Couch Mode.
5. With Discord configured and presence enabled, close/reopen Discord while a game continues.
6. Stop a disposable test game. Review Wine/Flatpak scope warnings. Keep an editor open on a
   game config file and verify it stays open. Check Stop All with only one game running.
7. Exercise save backup and restore using disposable saves.

Remote x86_64/aarch64 CI, the nonpublishing package workflow, package lifecycle checks and
current dependency scans remain release gates. ARM packages also require supported hardware
acceptance. Follow `RELEASING.md` after local testing and publication approval.
