# Omakade 1.13.0 local release candidate

This candidate combines the UI-quality work with the September 29 Couch navigation
and cold-start focus fixes. The maintainer reported completed local testing and
authorized release subject to the remaining automated checks. Package and CI gates
must pass before publication.

The exact commit, source archive, package hashes, validation logs and rollback
record are kept outside the source tree in
`/home/bts/.local/state/omakade-release-reviews/2026-09-29-1.13/`.
That prevents recording the candidate's identity from changing the identity itself.

## Scope

- Responsive Home, Library, Details and Settings; themed controls and shared metrics.
- Clearer Stats labels, repair actions and asynchronous availability checks.
- Verified save-backup copying during path relocation, with recovery and undo guards.
- Stop Game visibility, Nintendo prompts, logical Couch toolbar rows and cold-start focus.
- Five directional contracts and 16 cold-launch cases in the ordinary CTest suite.

The changelog distinguishes these changes from the emulator sources and Stats
features already shipped in 1.12.0. Stored observed intervals still use the existing
proportional Stats allocator. Interval-based allocation remains deferred.

## Automated release gates

Run Release build and the full CTest suite on this commit, release-tooling and
metadata checks, native Wayland startup probes in omabox, staging inspection,
package install/upgrade/remove/reinstall, and current dependency scans.
GitHub architecture CI and a nonpublishing Release workflow must pass before tagging.
Keep local validation separate from GitHub results and ARM64 hardware acceptance.

## Maintainer acceptance

The maintainer reported completed local testing on September 29 and explicitly
requested no repeated manual test. That acceptance and authorization are recorded
in the external candidate manifest. The behavioral source must remain unchanged
from the accepted local build; packaging and version changes receive automated
validation. Physical ARM64 acceptance must not be claimed from architecture CI.

The relevant local checklist is retained here as a coverage record:

1. Cold-launch with no mouse click. Confirm the real controller responds and its
   prompts match the device.
2. Briefly play one familiar Steam game and one emulator title. Confirm Stop Game
   closes only the intended game and each produces one correct session-history row.
3. Confirm the upgraded library, preferences and normal save behavior. Use
   disposable saves for relocation or restore acceptance.
4. Check TV/audio/streaming transport if included in the intended setup. An ARM64
   package also needs exact-package acceptance on supported ARM64 hardware.

Report the exact commit, package hashes, completed checks and known limitations
before publication. Acceptance is based on the maintainer's report, not the preview
video. Follow [RELEASING.md](../RELEASING.md), with the explicit no-repeat instruction
recorded for this release.
